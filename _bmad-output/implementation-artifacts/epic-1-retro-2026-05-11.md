## O que foi bem

1. **Stack ousada e moderna entregou** — Effect TS + Prisma v7 + Expo SDK 55 + NestJS v11 sem fallback para versões antigas. Bet pagou.
2. **Multi-schema Prisma desde o dia 1** — 6 schemas PostgreSQL criados na Story 1.2 evitaram refactoring depois.
3. **Pureza funcional do core foi mantida** — zero imports `@nestjs/*` em todos os arquivos de `core/`, verificado em cada story.
4. **Shared kernel completo na 1.4** — RolesGuard, TenantGuard, EffectExceptionFilter, EffectSchemaPipe, ResponseWrapperInterceptor entregues juntos, com 52 testes.
5. **Mobile com offline-first já desde a fundação** — MMKV + expo-sqlite + TanStack Query persistido configurados antes da primeira tela real.

## O que não foi bem

1. **Curva do Effect TS pesada na Story 1.3.** 10 itens deferidos (Effect Composition Primitives, Typed Errors Eviscerated, Reckless Sync Event Dispatching, Process Teardown) revelam que conceitos centrais foram aprendidos na marra.
2. **Patches sequenciais em código novo.** Story 1.3 teve `Effect.tryPromise`, `Clock.currentTimeMillis`, stack-trace preservation, `Proxy`-based mock — todos descobertos via review depois da implementação inicial.
3. **Sprint planning desalinhado com dependências reais.** Story 3.1 foi implementada com `JwtAuthGuard comentado (TODO: Epic 2)` antes da 2.1/2.2 estarem prontas.
4. **Reviews adversariais sem calibração de severidade.** Patches críticos (RolesGuard bypass, race conditions) misturados com cosmético (HttpCode, ParseUUIDPipe) tiveram mesmo peso visual.

## Lições aprendidas

- **Padrões arquiteturais finais emergem do primeiro bounded context real, não do scaffolding.** O `domain-scoped runtime` (TRIP_RUNTIME) só apareceu na Story 3.1, não na 1.3.
- **Effect TS exige primitivas específicas em produção:** `Effect.tryPromise` (não `Effect.promise`), `Clock` do Effect (não `new Date()`), preservar stack via `{ cause: error }`.
- **Reviews encontram bugs reais que CI não pega:** Effect.promise vs tryPromise, falta de teardown safety, EventEmitter sem maxListeners, dist/ commitado.
- **Story de scaffolding pura (1.1) tem ROI de review baixo;** stories de _padrão arquitetural_ (1.3, 1.4) têm ROI alto.
